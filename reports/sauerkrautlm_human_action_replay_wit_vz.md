# SauerkrautLM Human Action Replay To WIT-VZ

This workflow converts the public `VAGOsolutions/SauerkrautLM-Doom-MultiVec-31k`
human gameplay action labels into a WIT-VZ-compatible replay dataset.

## Why This Is Replay-Derived

The public Hugging Face dataset exposes human action scores, tokenized ASCII
game view, and depth bins. It does not expose the original ViZDoom pose
trajectory needed for our `future_local_path` target.

Therefore the workflow does not recover the original human path. Instead it:

1. reads the sequential human action scores,
2. maps them to ViZDoom button vectors,
3. starts fresh ViZDoom `defend_the_center` episodes,
4. replays the human action sequence,
5. records RGB frames and ViZDoom pose at every replayed step,
6. builds normal WIT-VZ samples from the replayed pose trajectory.

The resulting GT is:

```text
human-action replayed future pose
-> current-pose local transform
-> future_local_path [forward, right]
```

It should be described as **human-action replay-derived GT**, not original
human trajectory recovery.

## Action Mapping

The source dataset documents four action scores:

```text
shoot, move_forward, turn_left, turn_right
```

The replay script maps them to this project button order:

```text
ATTACK, MOVE_FORWARD, MOVE_RIGHT, MOVE_LEFT, TURN_RIGHT, TURN_LEFT
```

Mapping:

```text
shoot        -> ATTACK
move_forward -> MOVE_FORWARD
turn_left    -> TURN_LEFT
turn_right   -> TURN_RIGHT
```

Scores greater than or equal to `--action-threshold` are activated. Use
`--argmax-if-empty` if every score is below threshold and one action should
still be applied.

## Build A Small Replay Dataset

```powershell
uv run --with datasets python scripts/replay_sauerkrautlm_human_actions_wit_vz.py `
  --run-id wit_vz_sauerkrautlm_human_replay_smoke `
  --episodes 2 `
  --episode-steps 120 `
  --action-threshold 0.5 `
  --argmax-if-empty `
  --build-samples `
  --future-sec 5 `
  --overwrite
```

Outputs:

```text
data/wit_vz/raw/wit_vz_sauerkrautlm_human_replay_smoke
data/wit_vz/processed/wit_vz_sauerkrautlm_human_replay_smoke
```

## Recommended Evaluation Use

Use this as a human-action replay hold-out:

- run the current checkpoint on the processed dataset,
- compare against CV / PointNav endpoint oracle / A* oracle if needed,
- state clearly that the source of behavior is human actions, while the
  trajectory labels are generated by replaying those actions in ViZDoom.

## Limitations

- The public dataset rows do not include original episode IDs, so rows are
  chunked sequentially by `--episode-steps`.
- Initial state and stochastic game state are not guaranteed to match the
  original recording.
- The source scenario is `defend_the_center`, so this is a narrow human-action
  domain rather than broad game navigation coverage.
